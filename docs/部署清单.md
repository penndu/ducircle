## 二、部署前检查

### 1. 容器网络（最容易卡住的一步）

应用容器必须和 1Panel 的 MySQL / Redis **在同一个 Docker 网络**，
否则容器内解析不到 `1Panel-mysql-wQr4` 这个主机名。

在 1Panel「容器」页面：

1. 找到应用容器（首次部署前先构建，见第四节）
2. 点「网络」→ 加入 `1Panel-mysql-wQr4` 所属的网络
3. 同样加入 `1Panel-redis-29uO` 所属的网络

验证（在应用容器内执行）：

```bash
getent hosts 1Panel-mysql-wQr4   # 有输出说明解析正常
```

### 2. 安全组 / 防火墙

只需要放行 22、80、443。**不要**放行 3306 和 6379。

```bash
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
```

## 三、环境变量

在网站目录下建 `.env`（**不要提交到 git**，已在 `.gitignore` 里）：

```bash
cd /opt/1panel/www/sites/ducircle.dusays.com/index
cp .env.example .env

# 生成密钥
echo "SECRET_KEY=$(openssl rand -base64 48)" >> .env
```

然后编辑填入：

```ini
DEBUG=false
BASE_URL=https://ducircle.dusays.com

MYSQL_HOST=1Panel-mysql-wQr4
MYSQL_PORT=3306
MYSQL_DATABASE=ducircle
MYSQL_USER=ducircle
MYSQL_PASSWORD=<见密码管理器>

REDIS_URL=redis://:<Redis密码>@1Panel-redis-29uO:6379/0
```

**三个容易配错的地方：**

- `MYSQL_HOST` 填容器服务名，不是 `127.0.0.1`
- `REDIS_URL` 有密码时必须写成 `redis://:密码@主机:6379/0`
  （冒号不能漏，否则 Redis 会当用户名解析）
- `SECRET_KEY` 换掉会让所有已登录用户掉线，部署后不要改

## 四、首次部署

> **镜像由 GitHub Actions 构建并推到 Docker Hub**，服务器只 pull。
> **部署是手动的**——GitHub 里不存SSH 私钥。
> 完整配置见 `docs/GitHub-Actions部署.md`。

```bash
cd /opt/1panel/www/sites/ducircle.dusays.com/index

# 拉代码
git pull origin main

# 拉镜像并启动（容器内会自动跑 alembic upgrade head）
docker compose -f deploy/docker-compose.yml pull
docker compose -f deploy/docker-compose.yml up -d

# 看日志确认迁移成功
docker logs -f ducircle
```

日志里应该出现类似：

```
数据库连接正常
Redis 连接正常
调度器已启动，任务：定时抓取, 过期数据清理, 统计快照, AI 摘要生成
```

如果看到 `Redis 不可用，限流与分布式锁将降级`，说明容器没接到 Redis 网络，
回去检查第二节。

## 五、反向代理

在 1Panel「网站 → 反向代理」里新增：

| 项 | 值 |
|---|---|
| 代理名称 | `ducircle` |
| 代理地址 | `http://127.0.0.1:9527` |
| 发送域名 | `$host` |
| WebSocket | 开启 |

SSL 证书在 1Panel 申请（Let's Encrypt 免费），强制 HTTPS。

**自定义错误页**（可选但建议）：502/504 页面加一句
"站点维护中，稍后再试"——抓取任务高峰时应用会短暂无响应，
裸的 nginx 默认页对用户不友好。

## 六、验证清单

部署完逐项确认，不要跳：

```bash
# 1. 健康检查
curl -s https://ducircle.dusays.com/health
# 期望：{"status":"ok","db":"ok","version":"0.1.0"}

# 2. 页面能打开
curl -sI https://ducircle.dusays.com/web/login | head -1
# 期望：HTTP/2 200

# 3. API 文档
curl -s https://ducircle.dusays.com/openapi.json | head -c 100

# 4. 容器状态
docker ps --filter name=ducircle
```

浏览器里再确认：

- [ ] `/` 首页正常
- [ ] `/web/register` 能注册
- [ ] 注册后跳转 `/web` 看到空状态引导
- [ ] 添加一个友链，点「抓取」，几秒后状态变为成功

## 七、日常运维

### 更新代码

两步：本地 push（Actions 自动构建镜像），再 SSH 部署。

```bash
# 本机
git commit -am "说明"
git push
# 等 Actions 变绿

# 服务器
cd /opt/1panel/www/sites/ducircle.dusays.com/index
git pull origin main
IMAGE_TAG=<版本号> docker compose -f deploy/docker-compose.yml pull
IMAGE_TAG=<版本号> docker compose -f deploy/docker-compose.yml up -d
```

`IMAGE_TAG` 不传则用 latest。指定版本号能确认拉到的确实是新镜像。

### 看日志

```bash
docker logs -f ducircle                    # 实时
docker logs --tail 200 ducircle            # 最近 200 行
tail -f /opt/1panel/www/sites/ducircle.dusays.com/index/logs/*.log
```

### 备份数据库

```bash
docker exec 1Panel-mysql-wQr4 mysqldump \
  -uducircle -p'<密码>' ducircle \
  > /opt/backup/ducircle-$(date +%F).sql
```

建议加到 crontab，每天一次：

```bash
0 4 * * * docker exec 1Panel-mysql-wQr4 mysqldump -uducircle -p'<密码>' ducircle | gzip > /opt/backup/ducircle-$(date +\%F).sql.gz
```

### 回滚

```bash
git log --oneline -5                    # 找到上一个 commit
git checkout <commit>
docker compose -f deploy/docker-compose.yml pull
docker compose -f deploy/docker-compose.yml up -d
```

数据库迁移不可自动回滚。如果新版本有破坏性迁移，
需要 `alembic downgrade -1` 后再回滚代码。

## 八、已知风险

| 风险 | 说明 | 应对 |
|---|---|---|
| Redis 未接网络 | 限流与分布式锁失效，可能重复抓取 | 部署后看日志确认 |
| AI 平台 Key 未配 | 用户只能用自己填的 Key | 在设置页填，或后台配环境变量 |
| 首次抓取压力大 | 新账号导入几十个友链会集中抓取 | 已限并发，必要时调 `CRAWL_CRON` 错峰 |
| Tailwind 走 CDN | 外网 CDN 不可用时页面无样式 | 上线后可改成本地构建 |
