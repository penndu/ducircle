## 三、调优过程中发现的 6 个真实缺陷

全部来自实测，不是推测。每一个都已修复并固化为回归测试。

### 缺陷 1：selectolax 1.0 破坏性变更

`from selectolax.parser import HTMLParser` 直接抛 ImportError——1.0 移除了默认的 modest后端，正确入口是 `selectolax.lexbor.LexborHTMLParser`（注意类名也不同）。

**修复**：新建 `app/parser/html.py` 兼容层，同时支持 1.x 与 0.x。

### 缺陷 2：头像选择器写错

写成 `.site-avatar img`，但 Hexo 实际是 `<img class="site-avatar">` —— class 与标签在同一元素上。

**影响**：所有站点头像解析失败。

### 缺陷 3：`/tags/python` 未被过滤

原正则 `^/(tag|tags|...)/\d*$` 要求后面跟数字，漏了真实存在的 slug 写法。标签页会混进文章流。

**修复**：改为 `(/.*)?$`。

### 缺陷 4：单字标题被误杀

`len(text) < 2` 的阈值把「书」「记」「诗」这类单字标题全过滤了。中文书���里很常见。

### 缺陷 5：Ark 主题指纹层完全失效

实测发现 akilar.top 全文 **0 个 `<article>`、0 个 `<h1>`、0 个 `<h2>`**，文章装在 `.aside-list-item > a.title` 里。这正是旧工具 15 个主题全部不覆盖、导致抓不到的原因。

**修复**：框架规则表补充社区通用类名。

### 缺陷 6：`.html` 永久链接被误判为资源

新增扩展名过滤时把 `.html` 也排除了，导致 Typecho 式永久链接（`/16433.html`）全部丢失。noionion.top 有 28 篇文章全被误杀。

**修复**：只排除真正的资源类扩展名。

## 四、结论

### 4.1 自动识别路线成立

**兜底层对 4/4 站点全部有效**。即使 RSS 完全不可用，仍能靠框架指纹救回所有测试站点。

### 4.2 但第3 层（通用推断）实测为0

值得如实说明：第 3 层在本次测试中**一次都没成功**。原因是前两层已拦截所有测试站点，第 3 层没有机会执行。

这不代表它无用，但也意味着它目前是**未经真实数据验证**的部分。建议上线后用 `crawl_logs.strategy_used` 统计其实际贡献，若长期为 0 则考虑简化或移除。

### 4.3 上线后如何持续优化

每条记录都写 `strategy_used`，后台可直接统计：

| 问题 | 数据依据 |
|---|---|
| 该加哪些框架规则 | 指纹识别为unknown 的站点占比 |
| 第 3 层是否有用 | strategy_used = heuristic 的占比 |
| 哪些站需人工介入 | 抓取失败列表 |

**这是持续优化规则覆盖的唯一依据**，不要靠人工统计。

### 4.4 用户自定义规则仍不可省

自动识别再完善，也覆盖不了所有自建主题。第 0 层用户自定义规则是最后兜底，且按需求（Q13=D）用户配了就完全信任、不做静默降级，失败会明确记日志。
